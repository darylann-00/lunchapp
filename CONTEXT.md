## What Luncharoo Is

A single-kid weekly lunchbox planner for parents. The parent signs in, sets up a kid profile and parent preferences once, then each week they open a wizard, tell Luncharoo anything special about that week (leftovers, activities, things to skip), and get a full lunchbox plan generated by Claude. Each day's lunchbox fills 5 slots (protein, carb, fruit, veggie, fun) plus separate snacks. They can regenerate individual slots they don't like, then generate a deduped grocery list from the approved plan.

**One-sentence pitch:** Luncharoo takes the weekly "what do I pack?" decision off your plate.

**Target user:** Parents packing school or camp lunches for one kid, especially those who want variety without the mental overhead of planning from scratch.

## What's Built and Working

- **Auth** — `SignIn` page: Google OAuth (primary) + magic link (fallback). PKCE flow. `RequireAuth` guard redirects unsigned users to `/signin`. `useAuth` hook tracks session and exposes `signOut`.

- **Onboarding** (`src/pages/Onboarding.tsx`) — multi-step form collecting kid profile (name, age, allergies, dislikes, likes, repetition preference, snack config, dietary flags, school rules) and parent prefs (lunchbox slot picker with protein always on, thermos toggle, snack toggle). Protected by `RequireAuth`. Redirected to from `RequireKid` guard when no kid exists.

- **BentoShell** (`src/App.tsx`) — four-tab shell (Lunch Plan / Grocery / Browse / Profile) inside a fixed 390px-wide card with the luncharoo visual theme. Week navigation arrows in the header (Lunch tab only). Custom PNG food icons (`FoodIcon`) for food-related visuals; hand-drawn SVG sticker icons (`UiIcon`, `src/components/UiIcon.tsx`) for all non-food UI — nav, wizard, grocery containers, profile/kid, and state indicators. The Browse tab renders `ComponentBrowser` in its own full-height container so its filter bar stays fixed.

- **WizardOverlay** (`src/components/WizardOverlay.tsx`) — full-screen overlay. Day chip selector (Mon–Fri) + chat-style notes input + quick-add stickers → "Generate Plan". Plan generates in the background and saves as `'draft'`; on completion the PlanReviewPane auto-opens.

- **PlanReviewPane** (`src/components/PlanReviewPane.tsx`) — full-screen overlay showing the full week's plan for review/editing. Each day shows lunchbox slots (food icon + slot label + component name + favorite/hide feedback buttons + regenerate button) and snacks below. Food-specific icons are matched via `getFoodIcon()` from `src/lib/foodIconMap.ts`. Feedback writes to `component_feedback` and influences future plan generation. "Approve Plan" finalizes a draft.

- **LunchPlanTab** (`src/components/LunchPlanTab.tsx`) — shows the active week's plan as lunchbox cards per day. Each card shows filled slots with food icon + component name, combo items combined. Snacks show food-specific icons matched by name. Draft plans show a "Review Plan" banner; finalized plans show an edit pencil. Empty state prompts the wizard.

- **GroceryTab** (`src/components/GroceryTab.tsx`) — generates a deduped grocery list for the current week's plan via `aggregateGroceryList` (pure function, no AI call — collects ingredients from plan components). Grouped by category with checkboxes.

- **ComponentBrowser** (`src/components/RecipeBrowsePane.tsx`) — the Browse tab. Fetches all components + user feedback on mount. Filter bar: search, category chips with food icons (All/Protein/Carb/Fruit/Veggie/Fun). Each component card shows name, category badge with food icon, tag pills, snack badge. Favorite and hide buttons per card. Feedback flows into plan generation (favorites boosted, dislikes excluded).

- **ProfileTab** (`src/components/ProfileTab.tsx`) — displays kid profile, active lunchbox slots, thermos status, and snack toggle. Edit mode opens Onboarding in compact mode with prefilled prefs. "Reset all data" deletes rows from Supabase via `clearAll`.

- **AI layer** (`src/lib/ai.ts` → `src/lib/planEngine.ts` + `src/lib/components.ts`) — `generateWeeklyPlan` delegates to `orchestrateWeeklyPlan` in `planEngine.ts`, a pure module with no browser dependencies. The engine accepts injected `CallModel` (transport) and `SupabaseClient` (DB). Stage 1 pulls candidate components from the `components` catalog grouped by category (allergens/dietary/dislikes filtered; favorites + on-hand ingredients boosted); Stage 2 asks Sonnet to fill 5 lunchbox slots per day using the 5-Slot Formula (protein, carb, fruit, veggie, fun) plus snacks, respecting combo items via `also_fills` and enforcing minimum 3 distinct physical components per lunchbox; Stage 3 invents and saves any gap components via `generateComponentForGap` + `saveAIComponent`. `aggregateGroceryList` is a pure function that collects ingredients from plan components. `regenerateSlot` generates a replacement component for a single slot.

- **Server-side plan generation** (`api/generate-plan.ts`) — single POST endpoint that runs the full 3-stage orchestration server-side (direct Anthropic calls, no proxy hops). Creates a user-scoped Supabase client from the JWT for RLS. Rate-limited to 3/min per user. `AppContext.startBackgroundPlanGeneration` calls this.

- **API auth** (`api/_auth.ts`) — `requireAuth` helper validates the Supabase JWT on every `/api/anthropic`, `/api/generate-plan`, and `/api/transcribe` request.

## App Flow

```
/signin  ←  RequireAuth redirect (no session)
     ↓  Google OAuth or magic link
/onboarding  ←  RequireKid redirect (no kid in Supabase)
     ↓
/  BentoShell
   ├── Lunch Plan tab
   │    ├── WizardOverlay (notes → background generate → draft)
   │    │    └── POST /api/generate-plan → Record<string, DayPlan> (saved as draft)
   │    └── PlanReviewPane (review/edit → finalize)
   │         └── regenerateSlot per lunchbox slot or snack
   ├── Grocery tab → aggregateGroceryList (pure function) → GroceryItem[]
   ├── Browse tab → component catalog with feedback
   └── Profile tab → edit Kid + ParentPrefs, sign out, reset
```

## Data Model

### Core concept: the 5-Slot Lunchbox Formula

Each day's lunchbox targets 5 slots: **protein**, **carb**, **fruit**, **veggie**, **fun**. A `Component` is a simple food item (not a recipe — no prep steps or cook times) that fills one primary slot and optionally additional slots via `also_fills` (e.g. a turkey sandwich fills protein + carb). Snacks are separate from the lunchbox; components tagged `can_be_snack: true` can be picked as snacks.

### Supabase Tables

| Table | Key columns |
|-------|-------------|
| `profiles` | `id` (auth user uuid PK), `kid` (jsonb), `parent_prefs` (jsonb) |
| `weekly_plans` | `id` (uuid), `user_id`, `week_start_date` (date), `status`, `days` (text[]), `items` (jsonb — `Record<string, DayPlan>`), `grocery_list` (jsonb), unique on `(user_id, week_start_date)` |
| `components` | `id` (uuid), `name`, `category` (protein/carb/fruit/veggie/fun), `ingredients` (jsonb), `also_fills` (text[]), `can_be_snack` (bool), `note`, `tags` (jsonb), `source` (curated/ai/user), `created_by` |
| `component_feedback` | `user_id`, `component_id` (composite PK), `reaction` (like/dislike/favorite) |

Migrations live in `supabase/migrations/`. The component catalog is seeded via `scripts/seed_components.ts` (~55 curated components). Run `npm run seed-components` (requires `SUPABASE_URL` + `SUPABASE_SERVICE_ROLE_KEY`).
